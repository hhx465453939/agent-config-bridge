# ADR-001 — 以 Claude Code 为权威源的单机配置桥接架构

```yaml

```

## 背景

一台开发机上并存多个 AI 编码 agent，每个 agent 的全局配置散落在自己的目录约定里。同名的 skill / 命令 / 子 agent / MCP server 需要在多处各存一份，人工维护必然漂移（本机实测：106 / 58 / 55 三档可见项数，规则文档两组不同 md5）。

存在的既有做法都是**一次性脚本**：bash 版硬编码三平台映射，Python 版绑定 package 语义，且都不覆盖 pi 与 Kimi。部分机器还用软链把通用技能目录指向 Claude 的技能目录。

## 决策

采用「**单一权威源 + 声明式目标端清单 + 复制式桥接器**」架构：

1. **权威源唯一**：`~/.claude`（skills / commands / agents / CLAUDE.md）与 `~/.claude.json`（mcpServers）。其余端一律为渲染目标，只读不写。
2. **声明式清单**：每个目标端一个 JSON 清单（`bridge/targets/<name>.json`），显式枚举受管路径与派生方式。结构知识全部落在清单里，代码不含任何"猜路径"逻辑。
3. **复制而非软链**：以目录/文件为单位复制，逐文件哈希比对决定是否写入。
4. **只增不删**：默认不删除目标端多余文件；删除需显式 `--prune`。
5. **密钥外置**：仓库内只出现 `${VAR}` 占位符；真实值来自仓库外 `secrets.env`（权限 600），缺失时 fail-closed。

## 被否方案与理由

### 方案 A：符号链接（`~/.agents/skills -> ~/.claude/skills`）

* 优点：零复制、天然实时同步。
* 否决原因：
  1. 目标端工具可能整目录重写（如自动更新时），软链会被替换成实体目录，静默失效；
  2. Windows 原生软链需要管理员权限，不可移植；
  3. 无法做逐文件审计（"哪 5 个文件漂移了"答不出来）；
  4. 无法备份/回滚。
* 处置：**兼容并报告**。`doctor` 检测到该软链时明确提示，是否移除由用户决定。

> **更新（2026-09-29）**：pi 目标端的 `~/.agents/skills` 现在是一条**声明式链接**—— manifest 显式声明，planner 校验指向，由工具在 adopt/apply 时自动创建，并走和其他内容一样的快照/撤回路径。Windows 上用 junction（普通权限即可创建），因此原否决理由第 2 条不再适用于这一条链接；其余目标端的技能仍然是复制式管理。

### 方案 B：再维护一份中立配置（如 `~/.config/agent-configs/` 作为真源）

* 优点：格式统一、与任何 agent 解耦。
* 否决原因：**又变成两份维护**。用户已经在 Claude Code 里改 skill，要求他再改一次中立源，等于把新债叠在旧债上。
* 处置：拒绝。权威源必须是他**已经在用的那一份**。

### 方案 C：通用 JSON→TOML 转换库

* 优点：一次写好，支持任意 TOML 特性。
* 否决原因：违反 C1（零第三方依赖）；且实际只需写出 codex 用到的受限子集（表头、字符串、字符串数组、嵌套表），自写 ~80 行可控。
* 处置：自写受限写出器，越界值报错而非静默降级。

### 方案 D：加密后把 secrets 入库

* 优点：单仓库自包含。
* 否决原因：加密库与解密口令仍需分发；口令一旦泄漏等同于明文；且公开仓库里出现密钥密文本身就会引发审查噪音。
* 处置：拒绝。仓库零真实值 + 仓库外 `secrets.env`。

### 方案 E：完全镜像（把目标端目录整树对齐源端）

* 优点：实现最简单，天然无漂移。
* 否决原因：会删除用户手写的私有配置（pi 的 `settings.json`、各端的模型/主题选择），风险不可接受。
* 处置：改为显式清单 + `--prune` 显式开启。

## 后果

### 正向

* 新增能力只需"改 Claude 侧 + 跑一次 apply"两步；
* 每一处的漂移都可以被 `diff` 量化；
* 换机成本从"逐端回忆配置"降为"clone + 填 secrets + apply"；
* 仓库自身可作为公开模板复用（不含任何本机真实值）。

### 负向 / 需接受

* 目标端手改会被下次同步覆盖 → 用备份 + 回滚 + `plan` 干跑缓解，并在文档中反复强调"目标端只读";
* 桥接器本身成为新的依赖点 → 用零依赖 + 可通读的代码规模 + `doctor` 自检缓解；
* 目标端格式随版本演进会导致派生失效 → 用结构断言 + 非静默失败暴露，而不是悄悄写坏配置。

## 脱敏铁律（本仓库强制）

任何提交到本仓库的文本（代码、文档、模板、注释、测试 fixture）**必须**满足：

| 禁止出现 | 正确写法 |
|---|---|
| 公网/内网 IP（含 RFC1918） | `<占位符>` 或从环境变量读 |
| 真实域名 / 子域名 | `<你的域名>` |
| 端口号 | `<端口>` 或变量 |
| 用户名路径（`home/<user>`、`Users/<user>`） | `os.homedir()` / `~` / `${HOME}` |
| API key / token / secret / 私钥 | `${VAR}`（值放仓库外 secrets.env） |
| 邮箱 | `<你的邮箱>` |
| 主机名 / SSH 别名 / 隧道服务名 | `<主机别名>` |
| 云资源 ID / 桶名 / 集群名 | `<资源占位符>` |

提交前自查：

```bash
bash scripts/scan-secrets.sh          # 工作区 + 全历史
git log --all -S'<可疑串>' --oneline  # 指定串的历史检索
```

一旦**历史**泄漏过真实值，只改最新 commit 不够，必须做全史清除后强推。
