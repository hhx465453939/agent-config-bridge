# PRD-20261124 · 门控误拦合法写入

## 用户问题

在 Windows + Git Bash 环境下，门控扩展反复拦截**本来合法**的写入，表现为：

1. 已把家目录下的目标路径加入 `write_roots` 白名单，但以 `~/` 或 `/c/...` 形式书写的
   命令仍被判为「越界写入」。
2. 只要命令里含箭头函数（`=>`），就被报出形如 `C:\Users\<user>\{if(...)return`
   的「写入目标」——这段根本不是路径，而是代码片段。
3. 常见的 `2>/dev/null` 会被报成写入 `\dev\null`。

结果是：agent 无法完成任何文件写入，而用户明明已经配置了白名单。误拦比漏拦更伤，
因为它让「已授权」这件事失去意义。

## 期望

- 白名单里的路径，无论用户用 `~`、`/c/...` 还是 `C:\...` 哪种形式书写，都能正确命中。
- 命令里的非路径片段（代码、运算符）不得被当作写入目标。
- 真正的越界写入仍然拦住，安全性不下降。

## 验收

见 `SPEC.md` 的 AC-1 ~ AC-6。
