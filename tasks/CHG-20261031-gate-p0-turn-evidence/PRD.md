# PRD · 承诺什么 / 不承诺什么

## 承诺

| # | 承诺 | 用户可感知的结果 |
|---|---|---|
| P-1 | 模型只输出「稍后再做 / 后续补」而不动手时，会被强制继续 | 不再出现「说完了就算交付」 |
| P-2 | 读文件证据有有效期，过期需重读 | 「会话开头看过、结尾乱改」被挡住 |
| P-3 | 索引过期在**没有** `.codebase-memory` marker 的机器上也能识别 | Layer 2 从名存实亡变成真生效 |
| P-4 | 长会话不会因为前 30 次拦截而整体失去研究规则 | 30 次上限造成的「后半段放飞」消失 |
| P-5 | 安全规则（凭据、越界、破坏性）永远不受上限影响 | 不因封顶放过危险动作 |

## 不承诺

- 不承诺语义级判断「这段话是不是偷懒」。判据是有限的正则集合，宁可漏判也不误伤正常问答。
- 不承诺 no-slack 能覆盖用户主动要求「先给方案、暂不实现」的场景——那类文本应显式说明「按你的要求本次只出方案」。
- 不承诺自动重建索引；只负责在索引看起来过期时拦截并给出正确动作。
- 不承诺把 `index-before-read` 默认打开（全局索引没有 marker，仍保持 opt-in）。

## 边界条件

- no-slack 只看**助手最终文本**；工具结果、用户输入、系统消息不参与判定。
- 代码围栏（```）与引用块（>）内的文本不参与 no-slack 判定。
- 索引证据只认本会话成功完成的 `index_repository` / `detect_changes`；失败调用不记证据。
- 目标文件在本会话内被自己写过时，索引过期检查继续豁免（写入必然比索引新）。
