## 0. 一句话结论

**代码本身是空仓（无历史债）；真正的债在被治理对象上——即"同一份能力在 4~5 个目录里各存一份、且已经漂移"。** 本项目的价值就是把这笔债一次性清掉，并防止复发。

## 3. 债分类（相对本次变更）

| 分类 | 条目 | 处置 |
|---|---|---|
| **Before（变更前必须处理）** | 无（本项目为新建仓，无历史前提） | — |
| **During（本次变更加以解决）** | skill 跨端漂移；规则文档分叉；MCP 覆盖不全；MCP 明文凭据 | 纳入 CHG-001 范围（S1~S4） |
| **During（本次变更加以隔离）** | 源目录里的备份文件与平铺冗余；一次性老脚本 | **不删除**（用户资产，可能是他域在途改动），桥接器显式忽略并报告 |
| **After（变更后再议）** | 是否淘汰 `sync-skill-pool.sh` / `deploy-skills.py`；是否把 Claude `output-styles/` 纳入 | 交付后由 `iteration-manager` 决策 |
| **Accepted（明确接受）** | Windows 原生不支持；不做跨机同步 | 已写入 CHANGE.md 非目标 |

## 4. 架构热点 / 依赖与安全风险

| 项 | 评估 |
|---|---|
| 依赖风险 | 目标为零第三方依赖；若最终引入 TOML 解析库，需评估供应链（备选：自写 60 行的受限 TOML 写出器，只支持 codex 所需子集） |
| 安全风险 | 🔴 高：MCP 配置含 3 类明文凭据（第三方服务 api_key、机构邮箱、本地代理地址）；桥接器必须保证"仓库零真实值" |
| 兼容风险 | 中：4 种配置格式各有版本演进；转换器按能力抽象并做 schema 断言 |
| 可运维性 | 中：必须有 `plan`/`doctor`/`rollback`，否则出错难恢复 |

## 5. 文档漂移

* 本机规则主文档 `~/AGENTS.md` 与 `~/.codex/AGENTS.md` 内容不同（31804 vs 28233 字节），**且注入了同一批"铁律"的不同版本**；
* 两处文档都含本机专有信息（IP/域名/端口/路径），属于"个人资产"而非"可开源模板"——本项目仓库**只存模板与占位符**，真实渲染结果留在本机。

## 7. 结论与下一步

1. 无需为"代码债"做任何前置清理（空仓）；
2. 本项目的接受门槛应**高于常规项目**：一旦桥接器出错，会污染 5 个 agent 的全局配置 → `plan`/备份/回滚是 P0 而非 P2；
3. 下一步：`PRD.md`（产品契约）→ `SPEC.md`（工程契约）→ 用户批准后进入 `goal-driven-development`。
