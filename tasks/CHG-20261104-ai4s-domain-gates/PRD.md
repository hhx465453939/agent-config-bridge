# PRD · 承诺什么 / 不承诺什么

## 承诺

| # | 承诺 | 用户可感知的结果 |
|---|---|---|
| P-1 | 门控能认出「这个会话在做 AI4S 研究」，并只在该域启用研究规矩 | 普通开发仓库不会被 Worklog / 结果说明文件之类的规矩误伤 |
| P-2 | 判定有三层兜底：指纹 → 强关键词 → 模型；判不出来就落到 `general-dev` | 判定失败不会挡住工作，只会少一层规矩 |
| P-3 | 跑分析脚本前必须有一份新鲜的 Worklog | 「先想清楚再跑」变成硬约束，而不是口头建议 |
| P-4 | 分析脚本必须自带日志初始化，跑完必须留下同名 `.log` | 每次运行都可追溯，不用回到会话里翻输出 |
| P-5 | 结果目录里必须有说明文件 | 半年后打开 `results/` 知道每个子目录是什么，而不是一堆无主图表 |
| P-6 | 产物类问题只「再要一轮」，不阻塞 | 漏写说明文件是补写就能解决的事，不该卡死流程 |

## 不承诺

- 不承诺域判定 100% 准确。它只决定「应用哪组检查」，判错的代价是多/少一层规矩，而不是能不能干活。
- 不承诺 W3（文献验证）正确性。正则只能证明「写了 PMID」，证明不了「PMID 对得上」，本阶段不做硬拦。
- 不承诺覆盖所有 AI4S 子域。本阶段只落地干实验（`ai4s-dry-lab`）；量化（`ai4s-quant`）只留骨架，域检查为空。
- 不承诺模型判定一定可用。`external_judge` 只有字段与开关，不实现调用；没有 `modelHint` 时 T2 直接跳过。

## 边界条件

- **指纹**：只看文件是否存在（`docs/STATE.md` + `docs/WORKLOG.md` 同时存在 ⇒ 干实验），不读文件内容——研究数据不进日志。
- **强关键词**：必须命中 ≥2 个互不相同的强词才锁定域；只有弱词（如「什么是单细胞」）不锁定。
- **Worklog 窗口**：`worklog_ttl_ms` 默认 1800000（30 分钟）。窗口内更新过就放行。
- **「首跑」**：同一脚本路径在本会话内只判一次；第二次起不重复要求 Worklog，避免长任务被反复打断。
- **产物检查时机**：只在 `turn_end` 跑，不在 `tool_call` 跑——`tool_call` 加检查会给每次调用加延迟。
- **`general-dev`**：既有 checks 逐条不变、顺序不变，是新体系里的「什么都不加」。

## 未决问题

- `ai4s-quant` 的域检查（因子 IC / 回测日志）留到下一 CHG，本阶段只保证骨架能被识别、不误伤。
- 模型判定的超时阈值（默认 8000ms）是按本机实测拍的，没有跨机器基准。
