# PRD · 破坏性指令门控需要一个可一劳永逸设置的 bypass 挡位

## 背景（用户可感知的故障）

用户在交互式 pi 会话里跑长任务（几小时到通宵）。破坏性命令门控在 `confirm` 档弹窗询问，
会话就停在那里等一个人点按钮——而那个人睡了。

用户原话：

> 「有些任务不停的请示，卡在那里，有些彻夜运行的任务就会被卡住，很浪费时间」
> 「必须要有，而且可以配置全局模式是不是进入 bypass，就是可以直接用 / 命令，
>   选择这个 gate 的模式，然后一劳永逸修改门控模式」
> 「就是这种破坏性指令可以 bypass 和拒绝之间分挡位，**其他的都不牵扯**」

现有机制为什么不够：

| 现有手段 | 为什么救不了 |
|---|---|
| 弹窗里选「本会话允许这一类」 | 只覆盖一个类别；七类要撞七次；每个新会话重来 |
| `/gate grant <类别>` | 一次一个类别，要预判会撞到哪几类 |
| `destructive_confirm_mode: false` | 方向反了（更紧），且只作用于 confirm 档 |
| 无 UI 自动放行 | 用户是**有 UI** 的交互会话，走不到这一支 |
| 整个 revoke 掉门控 | 得到「什么都能干」，连红线带研究规则全没了 |

## 承诺

| # | 承诺 | 用户可感知的结果 |
|---|---|---|
| P-1 | 破坏性指令门控多一个全局模式开关 | 敲 `/gate mode` 看到当前模式并选择 |
| P-2 | 一条命令一劳永逸 | `/gate mode bypass` 一次设置，之后所有会话不再为删除/force push/DDL 弹确认 |
| P-3 | 可以只对当前会话生效 | `/gate mode bypass session` 不写盘，重开会话自动回 enforce |
| P-4 | 可以自动到期 | `/gate mode bypass 8h` 一夜无人值守，早上自动收紧 |
| P-5 | bypass 不等于裸奔 | 删 `$HOME`/cwd/含 `..`/顶层目录/git 根、磁盘格式化、裸设备写入、关机重启**仍然硬拦** |
| P-6 | **其他门控一条都不牵扯** | 图谱优先、思考前置、CHG 契约、AI4S、密钥写入、越界写入、no-blind-retry、no-slack 照旧执行 |
| P-7 | agent 不能自己切到 bypass | 写 `destructive_mode` 的写入被 `no-self-grant` 拒绝；只有用户敲命令能切 |
| P-8 | bypass 是可见的 | 会话启动、`/gate list`、`/gate mode` 都明示当前模式与剩余时间 |
| P-9 | 两端都遵守 | pi 与 dsh 从同一份 config 读模式；dsh 启动时告警 |
| P-10 | 可回退 | `/gate mode enforce`；或删机器本地 override 里的两个键 |

## 不承诺

| # | 不做 | 原因 |
|---|---|---|
| N-1 | bypass 下不再拦「不可恢复」红线 | 那正是 ADR-012 记录的「把过严换成裸奔」 |
| N-2 | bypass 下放过图谱/契约/AI4S/密钥等非破坏性规则 | 用户明确要求「其他的都不牵扯」；那些是纪律不是打扰 |
| N-3 | bypass 下允许 agent 改授权表/模式开关 | 否则一次写入即可自我提权，门控变成装饰 |
| N-4 | 按命令/正则白名单做 bypass | ADR-012 方案 C 的变体，正则本身是新风险面 |
| N-5 | 猜测「用户现在没看屏幕」自动进 bypass | 无法可靠判定，制造虚假安全感 |
| N-6 | 把 bypass 做成默认值 | 默认必须最严格 |
| N-7 | 给 dsh 加 `/gate` 命令通道 | dsh 没有命令 API；本 CHG 只保证它读同一份模式配置 |

## 验收口径

以 SPEC §「验收」的 AC-1…AC-20 为准；每条都要有实测证据写进 `TRACEABILITY.md`，
由 `bridge/test/gate-bypass.test.js` 自动执行。
